# ПК-версия w0y (Windows + Linux): разведка и паритет с Android

Версия `0.0.4-beta-1`, ветка `feat/desktop-0.0.4`. Документ ведётся вместе с кодом.

## 1. Что было на старте (по коду, а не по описанию задачи)

Описание задачи частично устарело, поэтому первым делом проверено, что есть на самом деле:

| Вопрос | Факт на старте |
|---|---|
| Фреймворк | уже **Compose Multiplatform Desktop** (отдельный Gradle-проект `desktop/`, ~7 000 строк), а не «урезанный» прототип |
| Общий код с Android | подключается исходниками (`sharedSources`): разбор ответов YouTube (`YtJson`), `SongItem`, `SyncMerge`, `CleanMatch`, `Profanity`, иконки, `SpectrumAnalyzer`, строки (`strings.xml` Android) |
| Языки | **уже четыре** (ru, en, uk, pl) из тех же `strings.xml`, что у Android; «только русский» в README был устаревшим |
| Звук | процесс `mpv` + IPC по Unix-сокету, `mpv` должен стоять в системе; на Windows сокет не работает |
| Вход | отдельное окно Chromium-браузера по CDP (порт отладки) + ручная вставка cookie; куки лежали **открытым текстом** в `library.json` |
| Данные | один `library.json` в `~/.local/share/w0y` (не Room), настройки внутри него |
| Вид | Pixel и Smooth; Hairline не было |
| Сборка | `createDistributable` на Linux в CI, без Windows |

## 2. Архитектура: оставлен и достроен общий Compose Desktop

Решение: **не переписывать**, а достроить существующий Compose Desktop. Причины по критериям задачи:

- **Одна кодовая база для логики и экранов.** Android на Compose, ПК на Compose; общее подключается исходниками. Kotlin Multiplatform-модуль с переносом всего Android-кода на `commonMain` дал бы большее совпадение, но потребовал бы переписать слой данных Android (Room, DataStore, Hilt, Media3) и риск для Android, который по условию нельзя ломать.
- **Скорость на слабом ноутбуке.** Нативный JVM-образ 158 МБ, холодный запуск до окна ≈ 2,4 с, 340 МБ в покое, ≈0,3% ядра (замеры ниже). Кроссплатформенный WebView/Electron был бы тяжелее.
- **Упаковка.** `createDistributable` даёт образ для обеих ОС; поверх Inno Setup (Windows) и appimagetool (Linux).
- **Цена решения.** Часть Android-экранов (годовой итог, «Быстрый выбор», «Мои файлы» с импортом аудио) на ПК не переносилась: нужен перенос логики с Room на файловое хранилище. См. таблицу.

Платформенные различия вынесены из общего кода:

| Интерфейс из задачи | Реализация |
|---|---|
| `AudioEngine` | `AudioEngine` → `LibMpv` (JNA, основной), `Mpv` (процесс + IPC, запасной на Linux) |
| `Paths` / открытие / уведомления / сон экрана / автозапуск | `Platform` |
| `SecureStorage` | `SecureText`: Windows DPAPI; Linux AES-GCM, ключ в Secret Service (`secret-tool`) или файл 0600 |
| `Updater` | `Updater` + общий с Android `UpdateCore` |
| `FilePicker` | `pickFolder` (zenity/kdialog/Swing), AWT `FileDialog` |
| `Tray` | Compose `Tray` |
| `GlobalShortcuts` | Linux: MPRIS и `w0y --do <команда>`; Windows: `RegisterHotKey` для медиа-клавиш (`WinMediaKeys`) |
| `MediaSessionBridge` | Linux: MPRIS; Windows: **только** медиа-клавиши, панели SMTC нет (нужен WinRT) |
| `AccountLogin` | `GoogleLogin` (Edge/Chrome/Chromium/Brave, найденный по известным путям) |

## 4. Звук на ПК

- Движок: **libmpv, вызываемая напрямую из JVM (JNA)**. Windows: `libmpv-2.dll` кладётся рядом с приложением CI. Linux: системная `libmpv.so.2`; при её отсутствии запасной путь — процесс `mpv`.
- Отклонение от задачи: «встроенная libmpv» на **Linux** не вшита в архив `tar.gz` (берётся из системы). В `.AppImage` CI **пытается** вложить libmpv с зависимостями (`installer/make-appimage.sh`); на этой машине не проверялось, поэтому в отчёте сказано как «не подтверждено».
- Найдено при проверке: JVM на Linux выставляет локаль пользователя, а libmpv отказывается работать при `LC_NUMERIC != C`. Перед созданием контекста вызывается `setlocale`.
- Тесты `AudioEngineTest` (настоящий libmpv, `ao=null`): воспроизведение, пауза, перемотка, один `eof` на трек, скорость + тон + реверб + эквалайзер, 200 переключений подряд без роста кучи.
- Позиция уходит в интерфейс не чаще 4 раз в секунду: нагрузка при воспроизведении снизилась с 22,7% до 8,2% ядра.

## 5. Замеры (Linux, EndeavourOS + Hyprland, 4 ядра, 11,7 ГБ ОЗУ)

Собранный `createDistributable`, диск в кэше, `W0Y_AO=null` (звуковая карта не используется).

| Показатель | Значение |
|---|---|
| Размер app-image | 158 МБ (Linux); установщик Windows и AppImage — только в CI, не измерены |
| Холодный запуск до окна | 2,30 / 2,37 / 2,42 с |
| Покой: ОЗУ / CPU | 331–348 МБ / 0,2–0,3% ядра |
| Воспроизведение: ОЗУ / CPU | 392 МБ / 8,2% ядра (до оптимизации: 415 МБ / 22,7%) |
| Старт трека (команда «играть» → позиция растёт, первый трек очереди после запуска) | ≈ 0,6 с |
| Прокрутка списка из 650 треков | 58–60 кадров/с |
| Windows: все показатели | **не измерены** (нет Windows-машины) |

## 6. Что проверено, что нет

Проверено на Linux: сборка, 24 теста ПК (движок звука, ядро, UI на трёх размерах окна, 8 вкладок настроек, смена языка, длинный список, перестановка за ручку, выделение), 242 теста Android, lint, `assembleRelease`, `createDistributable` + `w0y --smoke`, ручной просмотр Hairline-экранов и мини-плеера на Wayland/Hyprland.

**Не проверено** (нужен Windows/устройство): всё на Windows (установщик, DPAPI, медиа-клавиши, Edge-вход, трей, масштаб DPI, `RegisterHotKey`); `.AppImage` и вложенная libmpv; значок в трее на Hyprland; вход в аккаунт Google; восстановление копии на реальной библиотеке; обновление через GitHub с настоящего релиза.

Wine: тестовый запуск Windows-сборки через Wine не делался — для него нужен Windows JDK и нативные библиотеки (загрузки без явного разрешения не выполнялись).
